## このサイトについて

AtCoderを始めたばかりの頃は、アルゴリズム以前に分からないことがたくさんあります。

* AC / WA / TLE / RE って何？
* 制約を見てどうやって解法を決めるの？
* コンテスト中は何から始めればいい？
* A問題すら時間がかかるのはなぜ？
* レートはどう計算される？
* 問題が解けないとき、何を考えればいい？
* 他の人はどうやって勉強している？
* 一度挫折したけど、もう一度始められる？

このサイトでは、こうした「最初につまずくところ」をできるだけ分解し、
**競技プログラミングを始める → 問題を解く → コンテストに参加する → 続ける**までをまとめています。

## コンテスト中に使える逆引き

問題文を読んだ瞬間に、

**「この制約なら何を使えばいい？」**

を判断するための逆引き表を用意しています。

| 制約・特徴          | まず考えること           |
| -------------- | ----------------- |
| N ≤ 8          | 順列全探索             |
| N ≤ 20         | bit全探索            |
| N ≤ 100        | 三重ループ             |
| N ≤ 3000       | 二重ループ・DP          |
| N ≤ 2×10⁵      | ソート・map・累積和・二分探索  |
| N ≤ 10¹²       | √N探索など            |
| 巨大な値           | 二分探索・数式           |
| グリッド           | BFS / DFS         |
| 最短距離           | BFS               |
| 連結・島・かたまり      | DFS / Union-Find  |
| 何通り・場合の数       | DP                |
| 区間の和           | 累積和               |
| X以上 / X以下の個数   | ソート + lower_bound |
| 重複を除く          | set               |
| 出現回数           | map               |
| 最大 / 最小を繰り返し取得 | priority_queue    |

さらに、よくある問題文の表現から解法を逆引きできるようにしています。

# 問題が解けないときの考え方

このサイトで特に重視している部分です。

競プロでは、

> 「問題が解けない = 自分に才能がない」

とは限りません。

実際には、

* 制約を確認していない
* 問題文を正しく読めていない
* サンプルを手で追っていない
* 全探索できることに気づいていない
* 計算量を考えていない
* 使えるアルゴリズムを知らない
* 実装方法が分からない
* WAの原因を切り分けられていない
* コンテスト中の判断に慣れていない

など、原因は細かく分解できます。

「解けなかった」という一つの結果を、
**具体的な原因に変換するための考え方**もまとめています。

# このガイドの考え方

このサイトで大切にしているのは、

> **「難しいアルゴリズムを知っているか」だけではなく、
> 「分からないときに何を確認すればいいかを知っているか」**

ということです。

競プロを始めたばかりの頃は、

```text
問題を見る
 ↓
分からない
 ↓
自分には無理だと思う
 ↓
競プロをやめる
```

となりがちです。

このサイトでは、これを

```text
問題を見る
 ↓
制約を見る
 ↓
問題文を分解する
 ↓
サンプルを確認する
 ↓
候補となる解法を絞る
 ↓
実装する
 ↓
WA / TLE / RE を切り分ける
 ↓
必要なら解説を見る
 ↓
次に活かす
```

という流れに変えることを目指しています。
